# Project Git Commit Rules

All git commits in this repository must strictly adhere to the `[NAMESPACE] Description` convention defined below:

## Namespaces
- `[ADD]` - New features, files, or capabilities.
- `[FEATURE]` - Enhancements to existing features.
- `[DELETE]` - Removal of features, files, or deprecated code.
- `[REFACTOR]` - Refactoring code without behavior changes.
- `[FIX]` - Bug fixes and issue resolutions.
- `[DOCS]` - Documentation updates.
- `[TEST]` - Adding or modifying tests.
- `[CONFIG]` - Configuration file changes.
- `[STYLE]` - Code style, formatting, whitespace adjustments.
- `[PERF]` - Performance improvements.
- `[BUILD]` - Build scripts, dependencies, or toolchain updates.
- `[CI]` - CI/CD pipeline changes.

## Guidelines
- Always keep commits atomic and focused.
- Ensure clear, descriptive commit messages.
- Format code cleanly before creating commits.
